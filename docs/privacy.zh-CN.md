# 隐私与威胁模型

[English](privacy.md) | 简体中文

## 需要保护的资产

- 调用用户或子进程可以访问的凭据；
- 私有路径与仓库文件名；
- 命令 stdout/stderr 与错误文本；
- 仓库修订版和未提交状态元数据；
- 开发者工作树的完整性；
- 已发布源码和发布产物的完整性。

## 信任边界

用户、配方、仓库、通过 `PATH` 解析的可执行文件、操作系统、Git 二进制程序以及构建/
发布流水线都是独立的信任输入。ReproBrief 假定用户已经检查并信任配方及其启动的程序；
它不假定命令输出可以安全分享。

## 数据流与持久化

ReproBrief 自身不会发起网络请求。它会读取选定的 JSON 配方、不包含身份的平台字段，
以及 Git 的修订版、分支和 porcelain 状态。它运行声明的程序，捕获两个输出流中受上限约束的
前缀，然后写入本地报告。由于没有沙箱，子程序可以独立读取文件或使用网络。

环境变量值不会被序列化为字段。子命令会隐式接收一组最小的跨平台环境；传递其他环境变量
名称时，必须在配方中明确声明。这些额外变量的值会在持久化前登记为精确替换目标。

## 缓解措施

| 威胁 | 缓解措施 |
| --- | --- |
| Shell 注入 | 使用 `argv` 数组与 `shell=False`；配方不提供 shell 字段 |
| 目录逃逸 | 解析后的 `cwd` 必须位于仓库之内 |
| 输出死锁或耗尽 | 并发排空管道、每流保留字节上限与超时机制 |
| 超时后遗留子进程 | 新建 POSIX 会话/进程组，先终止再强制终止 |
| 意外覆盖 | 排他写入、所有权标记、分阶段替换与符号链接拒绝 |
| ZIP 路径/链接滥用 | 只打包生成的普通文件，并使用受控相对成员名 |
| 常见凭据或路径泄露 | 精确值替换与经测试的模式脱敏 |
| 终端预览泄露 | 在显示前遮罩可识别的敏感 `argv` 值 |
| 错误的安全感 | 在预览、报告、输出 README 和公开文档中显示警告 |
| 工作树静默变更 | 在命令前后采集 Git 状态；不自动回滚 |
| 供应链变更 | 没有运行时依赖；CI Action 锁定到完整提交；发布产物提供校验和 |

## 剩余风险

任何有限的正则表达式集都无法识别所有凭据或私有值。命令可以转换敏感值、将其与其他文本混合、
写入报告之外的位置、访问网络或修改仓库。超出字节上限而被丢弃的输出不会被分析。Git 状态中的
文件名本身也可能敏感。`PATH` 查找可能选中非预期的可执行文件。如果没有更强的平台专用
Job Object，Windows 上无法保证终止每个后代进程。

因此：

- 批准前先检查配方；
- 在你自己控制的独立沙箱中运行不受信任的项目；
- 使用可丢弃的测试凭据；
- 分享前检查每个报告文件；
- 不要把 ReproBrief 输出视为证明或安全通行证。
